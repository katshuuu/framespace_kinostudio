# API-контракт FrameSpace

Базовый адрес: `http://localhost:7070`. Тела запросов и ответов: `application/json`.

Заголовок `Authorization: Bearer <token>` нужен на всех маршрутах, кроме трёх открытых:

- `GET /api/health`
- `POST /api/auth/register`
- `POST /api/auth/login`

## Аутентификация

Регистрация принимает логин, пароль и ФИО. Вход принимает логин и пароль. Успешный ответ:

```json
{
  "token": "<jwt>",
  "tokenType": "Bearer",
  "expiresIn": 3600,
  "id": 1,
  "username": "admin",
  "fullName": "Администратор"
}
```

Логин состоит из 3–50 символов: латиница, цифры и знак подчёркивания. Пароль не короче 6 символов. Неверный логин и неверный пароль возвращают один и тот же текст `Неверный логин или пароль.` Токен живёт один час. Подпись — HMAC-SHA256. Секрет не короче 32 символов и берётся из переменной окружения `JWT_SECRET`. Пароль в токен не входит: перед записью он превращается в bcrypt-хеш.

Демонстрационный сотрудник, если логина `admin` ещё нет: `admin` / `admin123`.

## Операции

| Метод и путь | Действие |
|---|---|
| `GET /api/clients`, `POST /api/clients` | Список и создание клиента |
| `GET`, `PUT`, `DELETE /api/clients/{id}` | Чтение, изменение, удаление |
| `GET /api/locations`, `POST /api/locations` | Список и создание локации |
| `GET`, `PUT`, `DELETE /api/locations/{id}` | Чтение, изменение, удаление |
| `GET`, `POST /api/shooting-requests` | Список и создание заявки |
| `GET`, `PUT`, `DELETE /api/shooting-requests/{id}` | Чтение, изменение, удаление |
| `PATCH /api/shooting-requests/{id}/status` | Смена статуса по графу |
| `GET /api/statistics` | Показатели, как в меню «Статистика» |

Тело клиента: `fullName`, `email`, `phone`.

Тело локации: `name`, `address`, `capacity`, `type` (`PAVILION`, `OUTDOOR`, `STUDIO`, `OFFICE`).

Тело заявки: `clientId`, `locationId`, `title`, `description`, `shootingDate` в формате `гггг-мм-дд`, `durationHours`, `budget`. Новая заявка всегда получает статус `NEW`.

Смена статуса: `{ "status": "APPROVED" }`.

Список заявок принимает одно условие за раз, в таком порядке: `title`, `location`, `status`, пара `from` и `to`, `sort` со значением `date` или `budget`. Если параметр раньше в этом списке непустой, остальные игнорируются.

## Коды ответов

| Код | Когда |
|---|---|
| 200 | Успешное чтение или изменение |
| 201 | Запись создана, в том числе регистрация |
| 204 | Удаление без тела ответа |
| 400 | Пустое поле, дата в прошлом, недопустимый статус или переход |
| 401 | Нет заголовка Bearer или токен неверен |
| 404 | Нет записи с таким идентификатором или маршрут не найден |
| 409 | Дубликат уникального поля: почта, название локации или логин |
| 500 | Прочая ошибка SQL |

Тело ошибки: `{ "error": "текст" }`.

`BusinessException` становится ответом 400, кроме занятого логина: повторная регистрация выбрасывает `ConflictException` и получает 409. `EntityNotFoundException` становится 404. Состояние SQL `23505` становится 409.

Пустое название, несуществующий клиент, дата в прошлом и переход из `NEW` сразу в `COMPLETED` по-прежнему отклоняет `ShootingRequestService`. Удаление локации с активными заявками останавливается в `LocationService.delete`.
