# Киностудия — заявки на съёмку

Информационная система для учёта заявок на съёмку в киностудии. Хранит клиентов, локации (павильоны и площадки) и заявки на съёмку, помогает искать, фильтровать и анализировать их.

Проект развивался в два этапа на одной базе данных PostgreSQL:

| Этап | Интерфейс | Описание |
|---|---|---|
| КР №1 | Консольное меню | CRUD, поиск, фильтры, статистика, экспорт в Excel |
| КР №2 | Десктопное приложение JavaFX | Вход и регистрация, роли, таблицы, диалоги, графики, экспорт .xlsx / .csv |
| КР №3 | Spring Boot REST backend | JWT, PostgreSQL + Flyway, Docker Compose, Swagger, web UI — см. `README_KR3.md` |

КР №1 и КР №2 используют одни и те же слои `service` и `repository`. Backend КР №3 лежит в каталоге `backend/` и предоставляет REST API для Android (КР №4).

## Возможности

- Вход и регистрация. Обычные пользователи регистрируются сами, администратор один (логин и пароль в `.env`).
- Роли: пользователь просматривает данные и работает с заявками, администратор дополнительно управляет клиентами и локациями, удаляет заявки и меняет статус.
- Три связанные сущности: клиенты, локации, заявки на съёмку.
- Поиск по нескольким полям, фильтры по статусу, локации и диапазону дат, сортировка.
- Смена статуса заявки по графу допустимых переходов.
- Статистика: заявки по статусам (график), суммарный бюджет, средняя длительность, количество клиентов и локаций.
- Экспорт в `.xlsx` и `.csv` (выгружается то, что показано в таблице).
- Проверка ввода с подсветкой полей и понятные сообщения об ошибках.

## Технологии

- Java 21, Maven
- JavaFX 21 (FXML + CSS)
- JDBC и PostgreSQL 16
- Apache POI (экспорт в Excel)
- Docker Compose (база данных)

## Быстрый старт

Нужны: Docker, Java 21 и Maven 3.9+.

```bash
# 1. Настройки подключения
cp .env.example .env          # Windows: copy .env.example .env

# 2. База данных в Docker (таблицы и тестовые данные создаются автоматически)
docker compose up -d db

# 3. Запуск приложения
mvn javafx:run
```

Войти можно администратором (`ADMIN_LOGIN` и `ADMIN_PASSWORD` из `.env`, по умолчанию `admin` / `admin12345`) или зарегистрировать нового пользователя в окне входа.

Полезные команды:

```bash
docker ps                      # контейнер kinostudio-db должен быть healthy
docker compose down            # остановить базу (данные сохраняются)
docker compose down -v         # остановить и удалить данные (нужно, если менялись DB_USER или DB_PASSWORD)
mvn package                    # собрать jar: target/kinostudio-crm.jar
```

Подробности запуска, режим «окно в браузере» и проверка архива преподавателя описаны в [README_KR2.md](README_KR2.md).

## Настройки (.env)

Параметры не хранятся в коде. Файл `.env` создаётся из шаблона `.env.example` и не попадает в git.

| Переменная | Назначение |
|---|---|
| `DB_HOST`, `DB_PORT`, `DB_NAME` | где находится PostgreSQL |
| `DB_USER`, `DB_PASSWORD` | логин и пароль базы |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | единый логин и пароль администратора |
| `DB_PUBLISHED_PORT` | порт PostgreSQL на вашем компьютере для Docker (по умолчанию 5433) |
| `NOVNC_PORT` | порт окна приложения в браузере (необязательный Docker-режим) |

Порядок поиска значения: системное свойство (`-DDB_PASSWORD=...`), затем переменная окружения, затем файл `.env`.

Если используете свою установленную PostgreSQL, поставьте `DB_PORT=5432` и свой пароль.

## Архитектура

```
FXML → Controller → Service → Repository → PostgreSQL
```

- **Controller** читает поля формы и показывает результат, SQL и бизнес-правил не содержит.
- **Service** хранит бизнес-правила и бросает `BusinessException` или `EntityNotFoundException`.
- **Repository** единственный слой с SQL (JDBC, `PreparedStatement`).

Структура проекта:

```
src/main/java/ru/mirea/kinostudio/
├── Main.java                     консольная версия (КР №1)
├── model/                        Client, Location, ShootingRequest, User, enum-ы статусов, типов и ролей
├── repository/                   Repository<T> и реализации для каждой сущности
├── service/                      бизнес-логика, AuthService, статистика, фильтры
├── exception/                    BusinessException, EntityNotFoundException
├── util/                         AppConfig, DatabaseManager, PasswordHasher, экспорт в Excel и CSV
└── fx/                           приложение JavaFX (КР №2)
    ├── FxApp, Launcher           точка входа
    ├── AppContext                общие сервисы и данные
    └── controller/               контроллеры экранов и диалогов

src/main/resources/
├── fxml/                         разметка экранов
└── css/app.css                   стили

sql/schema.sql                    таблицы и тестовые данные
sql/users.sql                     таблица пользователей
docker-compose.yml                PostgreSQL в Docker
```

## Бизнес-правила

1. Название и описание заявки не могут быть пустыми.
2. Заявку нельзя создать на несуществующего клиента или локацию.
3. Дата съёмки не может быть в прошлом.
4. Длительность съёмки больше 0, бюджет не отрицательный.
5. Разрешены только заданные переходы статуса:
   `NEW → APPROVED | REJECTED`, `APPROVED → IN_PROGRESS | CANCELLED`, `IN_PROGRESS → COMPLETED | CANCELLED`.
   Из `COMPLETED`, `REJECTED` и `CANCELLED` переходы запрещены.
6. Название, адрес и вместимость локации обязательны, вместимость больше 0.
7. Нельзя удалить локацию, на которую есть активные заявки (не завершённые, не отклонённые и не отменённые).

## Безопасность

- Пароли хранятся только в виде хеша PBKDF2WithHmacSHA256 со случайной солью (16 байт, 120000 итераций).
- Пароль администратора и параметры базы берутся из `.env` и не попадают в репозиторий.
- Все SQL-запросы выполняются через `PreparedStatement`.
- После 5 неверных попыток входа вход для этого логина блокируется на 30 секунд.
